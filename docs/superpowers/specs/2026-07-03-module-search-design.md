# 模块搜索设计

**日期：** 2026-07-03

## 目标

为客户中心、项目中心、销售中心、产品中心增加真实搜索能力。搜索应直接作用于后端列表接口，避免仅对当前前端已加载数据做本地筛选。

## 范围

本次仅覆盖以下四个模块：

- 客户中心
- 项目中心
- 销售中心
- 产品中心

不在本次范围内的内容：

- 组合高级筛选
- 排序器
- 搜索历史
- 全字段模糊检索
- 左侧树结构搜索
- 分页重构

## 交互方案

### 统一交互

四个模块的列表区域顶部统一增加：

- 一个关键词输入框
- 一个“搜索”按钮
- 一个“重置”按钮

行为规则：

- 输入关键词后，按回车或点击“搜索”，向后端列表接口发起请求
- 点击“重置”后，清空关键词并恢复默认列表
- 搜索请求为真实搜索，前端不再依赖本地数组过滤来完成主搜索功能
- 搜索框默认提示语应体现当前模块的主要搜索字段

### 产品中心特殊规则

产品中心保留当前左侧树 + 右侧型号列表结构：

- 左侧树不做搜索
- 搜索只作用于右侧型号列表
- 当前树节点仍然是搜索范围约束的一部分
- 即：先按树节点限定，再按关键词搜索

## 搜索字段

### 客户中心

只搜索以下字段：

- `Organization.name`
- `Organization.region`
- `Organization.org_type`

理由：这些字段就是客户中心主列表和客户识别最常用的信息。

### 项目中心

只搜索以下字段：

- `Project.name`
- `Project.customer_org.name`
- `Project.sales_person.name`
- `Project.project_stage`

理由：项目列表主要按项目名、所属客户、销售负责人和阶段定位，不需要把项目备注、公司补充字段全部纳入。

### 销售中心

只搜索以下字段：

- `Person.name`
- `Person.phone`
- `Person.email`

并继续保留仅展示 `person_type = sales` 的现有约束。

### 产品中心

只搜索以下字段：

- `DeviceModel.model_name`
- `DeviceModel.model_code`
- `DeviceModel.product.name`
- `DeviceModel.product_version.version_name`

理由：型号检索本质上是按型号、产品、版本定位，搜索维持在这四个核心识别字段即可。

## 后端设计

### 接口策略

不新增专门搜索接口，直接扩展现有列表接口，统一使用查询参数：

- `?search=<keyword>`

这样可以保持 API 结构稳定，减少前端改造面。

### 查询实现

在对应 `ViewSet.get_queryset()` 中读取 `request.query_params.get('search')`。

实现要求：

- 无 `search` 参数时，行为与当前完全一致
- 有 `search` 参数时，对指定字段做 `icontains` 过滤
- 关联字段搜索使用 Django ORM 跨表查询
- 多字段之间使用 `OR` 关系
- 结果仍保留原有排序逻辑

### 产品中心列表接口

产品中心当前前端会分别请求：

- `product-lines`
- `products`
- `product-versions`
- `device-models`

本次真实搜索只作用于 `device-models` 列表请求。树结构相关接口保持原样。

若当前树节点存在，前端需要把节点约束一起传给 `device-models` 请求：

- 选中产线：按该产线下产品对应的型号过滤
- 选中产品：按该产品对应型号过滤
- 选中版本：按该版本对应型号过滤
- 再叠加 `search` 关键词

如当前接口还不支持节点约束参数，则在本次一并补齐，但只对 `device-models` 列表生效。

## 前端设计

### 客户中心

在左侧组织树右侧详情页顶部增加搜索栏。搜索作用于客户组织主列表/树数据来源，而不是详情 tab 内部表格。

预期提示语：

- `搜索客户名称 / 区域 / 类型`

### 项目中心

在项目列表顶部增加搜索栏。

预期提示语：

- `搜索项目 / 客户公司 / 销售 / 阶段`

### 销售中心

在销售列表顶部增加搜索栏。

预期提示语：

- `搜索销售姓名 / 电话 / 邮箱`

### 产品中心

在右侧型号列表区域顶部增加搜索栏。

预期提示语：

- `搜索型号 / 编码 / 产品 / 版本`

## 错误处理

- 搜索请求失败时，沿用现有错误提示方式
- 空关键词应视为默认列表，而不是错误输入
- 搜索结果为空时，正常显示空列表，不额外弹错

## 测试与验证

### 后端

至少补充以下自动化测试：

- 客户中心：关键词能命中名称/区域/类型
- 项目中心：关键词能命中项目名/客户名/销售名/阶段
- 销售中心：关键词能命中姓名/电话/邮箱，且不返回非销售人员

### 前端

至少验证以下行为：

- 输入关键词后能触发请求并刷新列表
- 重置后恢复默认列表
- 产品中心在树节点切换后，搜索仍只作用于当前节点范围
- 主要页面构建通过

## 风险与取舍

### 不做全字段搜索

优点：

- 查询更可控
- 结果更干净
- 便于后续索引优化

代价：

- 个别非常规字段不会被命中

这是本次明确接受的取舍。

### 不做高级筛选

优点：

- 改动范围集中
- 四个模块交互保持统一

代价：

- 复杂组合查询能力暂时不足

当前阶段优先保证统一真实搜索先可用。
