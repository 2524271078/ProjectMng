# 客户中心设备 Tab 同步与设备中心搜索设计

## 背景

当前系统已经新增独立“设备中心”，用于统一查看所有由项目中心同步生成的设备。但客户中心中的“已购设备”Tab 仍保留旧版展示口径，与设备中心在字段、搜索能力和视觉结构上不一致。

## 目标

在不扩大范围的前提下，同步以下两处体验：

1. `客户中心 -> 已购设备` Tab 与设备中心保持一致的设备列表字段和详情字段。
2. `设备中心` 新增真实搜索能力，并补齐更完整的工具区 UI。

## 范围

### 包含

1. 客户中心“已购设备”Tab：
   - 同步设备中心列表字段
   - 同步设备详情弹窗字段
   - 增加搜索栏
   - 统一局部 UI 风格

2. 设备中心：
   - 增加真实搜索
   - 优化顶部工具区布局与按钮层级

### 不包含

1. 不改 `客户中心 -> 关联项目 -> 项目详情 -> 项目设备`
2. 不改项目中心设备管理逻辑
3. 不抽离通用设备组件，避免本轮改动范围扩散

## 设备列表口径

客户中心“已购设备”和设备中心统一为以下字段：

1. 设备名称
2. 序列号
3. 当前保内状态
4. 服务开始
5. 服务结束
6. 客户公司
7. 客户联系人
8. 销售
9. 操作（详情）

## 设备详情口径

详情弹窗统一为以下结构：

1. 设备名称
2. 序列号
3. 客户公司
4. 客户联系人
5. 销售
6. 设备项目类型
7. 管理地址
8. 设备硬件码
9. 设备系统版本
10. 版本更新方式
11. 服务开始
12. 服务结束
13. 当前保内状态
14. 上架时间
15. 是否标品
16. 是否支持远程
17. 现场运维人员
18. 截图链接
19. 授权信息
20. 备注

## 搜索设计

### 设备中心

搜索走后端真实搜索，字段收口为：

1. `name`
2. `serial_number`
3. `customer_org__name`
4. 最新项目绑定对应 `customer_contact__name`
5. `sales_person__name`

说明：

1. 客户公司和销售优先使用设备自身归属，缺失时回退到最新项目绑定所属项目。
2. 客户联系人统一取最新项目绑定所属项目的联系人。

### 客户中心已购设备

客户中心中的设备搜索只在当前客户上下文内执行，不做全局检索。搜索字段收口为：

1. 设备名称
2. 序列号
3. 客户联系人
4. 销售

实现上优先复用当前客户概览数据做前端过滤，避免额外新增客户设备子接口。

## UI 设计

### 设备中心

1. 顶部增加输入框、搜索按钮、重置按钮、刷新按钮
2. 工具区左侧保持模块标题，右侧集中操作按钮
3. 表格列宽按扫描优先级调整，客户公司字段保留较宽空间

### 客户中心已购设备 Tab

1. 在 Tab 内容头部增加紧凑工具栏
2. 搜索栏与按钮风格对齐设备中心
3. 表格列定义和详情弹窗字段与设备中心一致
4. 保留客户中心本身的 Tab 容器结构，不做页面级布局重构

## 技术方案

1. 后端：
   - 扩展 `/api/devices/` 支持搜索参数
   - 搜索逻辑放在 `DeviceViewSet.get_queryset()`

2. 前端：
   - `DeviceDirectoryView.vue` 增加搜索状态、搜索动作和工具区样式
   - `CustomerCenterView.vue` 的“已购设备”Tab 补搜索区和统一列
   - 设备详情弹窗字段补齐客户公司、客户联系人、销售

## 风险与控制

1. 设备搜索涉及“最新项目绑定联系人”的查询口径，容易写成低效查询：
   - 通过在后端查询中补 `select_related/prefetch_related` 控制 N+1
2. 客户中心概览数据是整包返回：
   - 当前客户设备量通常小于全局设备中心，先用前端过滤即可
3. 设备详情字段同步时容易改到项目中心：
   - 本次仅改客户中心和设备中心，不动项目中心

## 验证

1. 后端新增设备搜索测试
2. 后端完整测试通过
3. 前端构建通过
4. 手工验证：
   - 设备中心可按设备名、序列号、客户公司、客户联系人、销售搜索
   - 客户中心已购设备列表字段与设备中心一致
   - 两处详情字段一致
