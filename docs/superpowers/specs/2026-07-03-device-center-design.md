# 设备中心设计

## 背景

当前系统中的设备入口分散在客户中心与项目中心内。客户中心只能按客户查看已购设备，项目中心则围绕单个项目管理项目设备。缺少一个独立的“设备中心”模块来统一查看所有由项目中心创建并维护的设备。

## 目标

新增独立“设备中心”菜单与页面，用统一列表展示所有设备，并提供与现有客户中心/项目中心一致风格的设备详情视图。

## 范围

1. 左侧菜单新增“设备中心”。
2. 新增设备中心页面，展示全量设备列表。
3. 列表字段至少包含：
   - 设备名称
   - 序列号
   - 当前保内状态
   - 服务开始
   - 服务结束
   - 客户公司
   - 客户联系人
   - 销售
   - 操作（详情）
4. 详情页展示风格与现有客户中心中的设备详情保持一致。

## 数据口径

1. 设备主数据来自 `Device` 表。
2. 服务开始、服务结束、保内状态来自该设备最新有效 `ProjectDevice` 绑定。
3. 客户公司优先取设备自身 `customer_org`，为空时回退到最新有效项目绑定所属项目的 `customer_org`。
4. 销售优先取设备自身 `sales_person`，为空时回退到最新有效项目绑定所属项目的 `sales_person`。
5. 客户联系人取最新有效项目绑定所属项目的 `customer_contact`。

## 接口设计

1. 继续使用现有 `/api/devices/` 列表接口。
2. 扩展 `DeviceSerializer` 返回：
   - `customer_org_detail`
   - `sales_person_detail`
   - `customer_contact_detail`
3. 继续复用 `/api/devices/{id}/overview/` 详情接口。
4. 扩展设备详情接口返回 `customer_contact`，与列表口径一致。

## 前端设计

1. 新增 `DeviceDirectoryView.vue` 作为独立设备中心页面。
2. 页面结构采用单页列表布局，不使用组织树。
3. 列表下方展示全量设备，点击“详情”打开详情弹窗。
4. 详情弹窗保持当前系统设备详情字段结构和视觉层级。
5. 当前“客户中心 -> 已购设备”先不调整，避免本次改动扩散。

## 验证

1. 后端新增接口测试，验证 `/api/devices/` 返回新增的客户公司、客户联系人、销售字段。
2. 后端新增详情测试，验证 `/api/devices/{id}/overview/` 返回客户联系人字段。
3. 前端构建通过。
