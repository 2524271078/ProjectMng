# 客户中心信息页签合并设计

## 背景

当前客户中心详情区外层使用 6 个并列页签：`客户详情`、`联系人`、`负责销售`、`设备`、`合同`、`项目`。

其中 `客户详情`、`联系人`、`负责销售` 都属于同一类客户主数据，拆成 3 个独立页签后有两个问题：
- 查看一个客户的基础信息时需要频繁切换页签，信息连续性差。
- 联系人和销售都属于客户主数据的一部分，和客户详情拆开后，页面结构显得过碎。

本次调整目标是把这 3 个页签合并为一个统一的 `客户信息` 页签，减少切换成本，同时不改动接口与后端数据结构。

## 目标

1. 将 `客户详情`、`联系人`、`负责销售` 合并为一个新的 `客户信息` 页签。
2. 保持 `设备`、`合同`、`项目` 页签不变。
3. 不改动现有接口、分页参数、详情查询和数据模型。
4. 保持现有联系人列表、销售列表的操作能力和分页能力。
5. 优先保证桌面端信息密度和可读性，不引入复杂响应式重排。

## 非目标

1. 不调整客户树和左侧筛选结构。
2. 不修改联系人、销售、设备、合同、项目的数据来源。
3. 不新增后端接口。
4. 不在本次中重做客户中心整套视觉风格。

## 方案概述

将客户中心外层页签重组为：
- `客户信息`
- `设备`
- `合同`
- `项目`

其中新的 `客户信息` 页签内部按纵向区块展示 3 部分内容：
- 客户详情
- 联系人
- 负责销售

用户进入任意客户后，默认进入 `客户信息` 页签，在同一屏内连续查看客户基础资料、联系人列表和销售列表，无需再在 3 个页签间来回切换。

## 页面结构

### 外层页签

原结构：
- `客户详情`
- `联系人`
- `负责销售`
- `设备`
- `合同`
- `项目`

新结构：
- `客户信息`
- `设备`
- `合同`
- `项目`

### 客户信息页签内部结构

按从上到下顺序排布：

1. `客户详情` 区块
- 继续使用现有描述信息组件风格。
- 展示客户名称、组织类型、区域等基础字段。
- 后续如果已有更多基础字段，保持在这个区块内集中展示。

2. `联系人` 区块
- 保留现有联系人表格。
- 保留现有分页。
- 如果当前页面已有联系人相关操作按钮，仍保留在本区块标题或工具栏区域。

3. `负责销售` 区块
- 保留现有销售表格。
- 保留现有分页。
- 如果当前页面已有销售相关操作按钮，仍保留在本区块标题或工具栏区域。

## 交互说明

1. 选择左侧客户后：
- 默认激活 `客户信息` 页签。
- 同步加载客户概览、联系人分页数据、销售分页数据。

2. 切换到 `设备`、`合同`、`项目` 页签：
- 延续当前按页签触发对应加载逻辑的方式。
- 不改变现有分页和搜索行为。

3. 回到 `客户信息` 页签：
- 已加载的客户概览、联系人分页、销售分页保持当前状态。
- 不强制额外清空分页，除非当前已有切换重置逻辑明确要求重置。

## 布局与样式原则

1. 使用单页签纵向分区，而不是左右双栏布局。
原因：当前客户中心内容宽度有限，左右双栏会压缩表格可读性，并增加适配成本。

2. 每个区块应具备统一的区块标题和上下间距。
建议结构：
- 区块标题
- 区块内容
- 区块底部与下一区块之间保留固定垂直间距

3. 联系人与销售表格优先沿用现有表格样式，避免为这次结构调整引入额外视觉风险。

## 实现拆分

### 模块 1：页签结构合并
- 将外层 `客户详情`、`联系人`、`负责销售` 合并为 `客户信息`
- 将三部分内容迁移到同一页签内部
- 保持现有数据源和交互逻辑不变

### 模块 2：样式收口
- 统一区块标题样式
- 统一区块间距、表格顶部留白和分页位置
- 确保桌面端展示紧凑且层级清晰

## 风险与处理

1. `handleCustomerTabChange` 现有逻辑可能依赖旧的 `base`、`contacts`、`sales` 页签名。
处理：梳理切换逻辑，将客户信息相关数据加载收口到新的 `info` 页签或客户选择动作中。

2. 联系人和销售列表从独立页签移入同屏后，页面初次加载成本会增加。
处理：优先复用已有分页接口；若实际体验可接受，则不额外引入懒加载复杂度。

3. 页面纵向长度会增加。
处理：通过清晰分区、间距控制和表格分页限制，避免单屏信息失控。

## 验证方式

1. 选择客户后，默认显示 `客户信息` 页签。
2. `客户信息` 页签内依次能看到客户详情、联系人、负责销售 3 个区块。
3. 联系人与销售列表分页仍可正常切换。
4. `设备`、`合同`、`项目` 页签行为不回归。
5. 前端构建通过。

## 结论

本方案采用“外层页签收敛、页签内分区展示”的方式，将客户主数据集中到一个 `客户信息` 页签中，减少客户中心在高频查看场景中的切换成本，同时保持后端接口、分页能力和现有业务逻辑稳定。
