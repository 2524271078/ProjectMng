# 第一阶段业务流程

## 1. 组织维护

在客户中心新增组织。`Organization` 通过 `org_type` 区分客户、厂商、第三方中标单位、集成商、内部公司。组织支持父级组织、简称、区域、地址、状态、备注和扩展字段。

## 2. 人员维护

在人员管理中新增人员。`Person` 通过 `person_type` 区分销售、客户联系人、内部人员、现场运维人员、厂商联系人。人员可绑定组织和 Django 用户。

## 3. 销售客户关系

通过 `SalesCustomerRelation` 绑定销售和客户，支持关系类型、起止日期、状态、备注和扩展字段。

## 4. 产品和型号

先维护 `Product`，再维护 `DeviceModel`。产品和型号均可绑定厂商组织，为后续厂商维保和采购统计预留扩展空间。

## 5. 设备维护

在设备中心新增真实设备实例 `Device`，绑定设备型号、客户组织、销售、现场运维人员。设备保留硬件编码、软件版本、规则库版本、授权信息、授权到期日期、上线/下线日期、基础信息图片和扩展字段。

## 6. 合同和采购链路

在合同中心维护 `Contract`。合同通过 `final_customer` 表示最终客户，通过 `direct_buyer` 表示直接购买方。`ContractParty` 按 `order_index` 表示采购参与方链路，解决客户不一定直接给内部公司下单的问题。

## 7. 合同绑定设备

使用 `ContractDevice` 绑定合同和设备，记录数量、价格和备注。设备详情和合同详情均可查看绑定关系。

## 8. 查询链路

- 从销售中心进入销售，查看负责客户、客户设备和合同。
- 从客户中心进入客户，查看联系人、负责销售、已购设备、关联合同。
- 从设备中心进入设备，查看客户、销售、运维、授权、合同和附件。
- 从合同中心进入合同，查看参与方链路和绑定设备。
